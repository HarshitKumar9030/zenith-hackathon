# Helper location tracking and Android demo

The website now offers a one-button **Share location** action for foreground tracking; the Android companion remains available for background sharing. Both require explicit permission and an active assignment. The Android companion shares location only after an approved helper pairs an assigned pickup, grants location/notification permission, and taps **Start sharing**. A visible foreground notification includes Stop. English and Hindi are supported. Residents see only their assigned helper. There is no public helper-location directory.

## Install and pair

Build from the repository root with `python3 web-app/android-helper/build.py`. Requires Android SDK platform/build tools and JDK 17+ (the script uses Android Studio's bundled runtime when available). Install `web-app/android-helper/build/waste-right-helper-debug.apk` on Android 8+ by opening it on the phone and allowing installation for the transferring app.

In the helper dashboard, open an assigned collection → Pair Android app. Enter the displayed server address and one-use code in the Android app. Use a deployed HTTPS server, or for the local hackathon debug build, the computer's LAN address with port 3001; phone and computer must share the network. `localhost` on a phone refers to the phone. Tap Pair, then Start sharing. Choose precise location for the best available GPS fix. Open the resident's Pickups page to see updates for location status and the arrival range. Select View live map to see the helper and collection-address markers.

Debug builds permit HTTP for LAN testing; use trusted local networks. A production release needs an HTTPS-only build, a private signing key, distribution setup, and physical-device/battery testing. APKs, keys and generated build files stay out of Git. The current APK was compiled and its signature verified; physical-device background tracking has not been verified.

## Behaviour and limits

GPS updates are attempted every five seconds while the foreground service runs. Android may delay them. The app does not request unrestricted background-location permission, silently restart after a reboot, or continue after its active task is removed. The notification can stop sharing at any time. Pairing expires after five minutes and is single use; the scoped tracking token remains in memory, expires after two hours, and applies to one pickup. A 15-second heartbeat checks whether assignment or authorization ended. Completion, reassignment, helper deapproval or password change revoke tracking. No complete route history is stored: only the latest fix, with TTL cleanup. Stale fixes disappear after two minutes.

The tracking card shows device-reported accuracy and update age, never an Apple Find My accuracy promise. GPS accuracy depends on hardware, permissions, buildings and signal. Map rendering is restored. Tiles are requested directly from OpenStreetMap only after the resident opens the map, with visible attribution and normal browser caching. The helper marker shows actual reported fixes; an accuracy circle shows uncertainty and the collection address has a separate purple marker. Panning pauses automatic following; Follow helper/Recenter restores it. Resize handling supports desktop and phone layouts. Tile failures show a retry action without hiding location details. No road route or travel-time API is configured. A fresh fix within 100 m reported accuracy plus a saved collection coordinate yields an approximate arrival range: straight-line distance at an assumed 10–25 km/h with a buffer. It is not road routing, traffic data, or a promised appointment. Otherwise ETA stays pending.

Verification: `npm test`, `npm run build`, and `node tests/tracking-integration.mjs` from `web-app/`. Integration uses a separate temporary MongoDB database and synthetic coordinates, with external email disabled.


Implementation references: [Leaflet 1.9.4 API](https://leafletjs.com/reference.html), [OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/). The default tile service is best effort, with no uptime guarantee; use a contracted tile provider before production-scale traffic. Precise GPS accuracy and Android background delivery still require physical-device testing. The map does not promise Apple Find My accuracy.


Browser sharing setup and lifecycle tests are documented in [production readiness](production-readiness.md). Browser tokens stay in memory, Stop/navigation clear the watcher and attempt session revocation, and failed permission/setup never starts a watcher. Keep the web screen open; use Android for background operation.

## Android dashboard (0.2, 26 October 2026)

The launcher now opens the online helper workspace at `https://wasteright.harshit.page`, with native Home, Collections, Earnings and Area navigation. Existing illustrated UI and English/Hindi helper controls are reused. Web sessions stay in WebView. A one-use code generated by the authenticated assigned helper passes through a top-frame custom navigation to native code; native exchanges it for the scoped tracking token. There is no JavaScript interface exposing native methods to frames. HTTPS host checks apply before accepting navigation; external links open separately. Location sharing remains explicit and has native notification/Stop controls. The older manual-pairing activity remains private for source compatibility.

Special jobs are labelled, searchable/filterable and display Operations' instructions. Claiming a special job requires `specialPickupApproved` server-side; unresolved handling cannot be claimed. Resident special requests enter Operations review without using reward credits or membership allowance. They are not ordinary scheduled pickups: Operations must provide terms and a price, the resident accepts/pays, and an approved helper then accepts the job.

The current deliverable is a debug-signed APK. Publish the matching web build to the configured domain before installation testing. Native GPS/background behaviour is not certified by the browser layout or API tests. See the Android README for installation and remaining field checks.
